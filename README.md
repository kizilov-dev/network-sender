# network-sender

Небольшой HTTP-сервис для проверки связи внутри приватной сети. По запросу снаружи он сам отправляет GET-запрос на указанный адрес и возвращает, что получилось: ответ, его статус и время или текст сетевой ошибки.

Работает в паре с [network-receiver](https://github.com/kizilov-dev/network-receiver), но запрос можно отправить на любой адрес и порт, например на сервис или базу данных в той же сети.

## Запуск

```bash
go build -o main .
PORT=8080 ./main
```

Нужен Go 1.22+. Порт задаётся переменной `PORT`, по умолчанию `8080`.

## Эндпоинты

| Метод | Путь       | Что делает                                       |
| ----- | ---------- | ------------------------------------------------ |
| GET   | `/`        | Страница с описанием и формой для запроса        |
| GET   | `/healthz` | Проверка здоровья, отвечает `ok`                 |
| GET   | `/send`    | Отправляет GET-запрос на `target` и отдаёт итог  |

### `GET /send`

Параметры:

- `target` — обязательный, полный URL: `http://10.0.0.5:8081/ping`
- `timeout` — таймаут в секундах, от 1 до 60, по умолчанию 10

```bash
curl "http://<sender>:8080/send?target=http://10.0.0.5:8081/ping&timeout=5"
```

Ответ, если удалось получить HTTP-ответ (с любым статусом):

```json
{
  "target": "http://10.0.0.5:8081/ping",
  "success": true,
  "latency": "1.2ms",
  "status_code": 200,
  "response_body": "{\"message\":\"pong\",...}",
  "content_type": "application/json; charset=utf-8",
  "content_length": "92"
}
```

Ответ при сетевой ошибке:

```json
{
  "target": "http://10.0.0.5:8081/ping",
  "success": false,
  "latency": "5.0s",
  "error": "... context deadline exceeded ..."
}
```

Тело ответа обрезается до 1000 символов. В исходящий запрос добавляются заголовки `X-Sender-App: network-sender` и `X-Request-Time`.

## Как читать результат

| Результат                                         | Что значит                                          |
| ------------------------------------------------- | --------------------------------------------------- |
| `success: true`                                   | Связь есть, сервис ответил                          |
| `connection refused`                              | Хост доступен, но порт закрыт                       |
| `EOF`, `malformed HTTP response`                  | TCP-соединение есть, на порту не HTTP (например, БД) |
| `context deadline exceeded`, `i/o timeout`        | Пакеты не доходят: нет маршрута или их режет фильтр |
| `no route to host`                                | Адреса нет в сети                                   |

Для портов с другим протоколом это тоже работает как проверка TCP. MySQL, например, сразу присылает приветствие, и оно видно в тексте ошибки `malformed HTTP response`.

## Проверка двух машин в одной сети

1. Запустите `network-receiver` на машине B, он слушает порт `8081`.
2. Запустите `network-sender` на машине A, ему нужен доступ снаружи.
3. Вызовите `/send` на машине A с приватным IP машины B:

   ```bash
   curl "http://<A>:8080/send?target=http://<приватный-IP-B>:8081/ping"
   ```

4. `success: true` и `"message":"pong"` в `response_body` значат, что связь по приватной сети есть. В ответе receiver есть поле `your_ip`: это адрес, с которого пришёл запрос, то есть приватный IP машины A.

Подробности каждого запроса сервис пишет в stdout с префиксом `[SEND]`.
